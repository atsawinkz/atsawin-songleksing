    ⚠️ กลยุทธ์ Healthy Class:
    - ไม่ต้องตี bbox (ไม่มีรอยโรคให้ตีกรอบ)

 Phase 4: Train + Evaluate RT-DETR
 สถานะ: ยังไม่เริ่ม | กำหนดเสร็จ: สัปดาห์ที่ 2-3
====================================================================

--- 4.1 เตรียมสภาพแวดล้อม ---
[ ] pip install ultralytics
[ ] ตรวจสอบ CUDA: python -c "import torch; print(torch.cuda.is_available())"
[ ] ยืนยัน dataset.yaml path ถูกต้อง (ดู Project/dataset.yaml)

--- 4.2 เทรนโมเดล ---
[ ] รัน Project/train_rtdetr.py
    พารามิเตอร์สำคัญ:
    - Model: RT-DETR-L (rtdetr-l.pt, pretrained COCO)
    - imgsz: 640 | batch: 8 (ปรับเป็น 16 ถ้า VRAM พอ)
    - epochs: 100 | patience: 15 (Early Stopping)
    - optimizer: AdamW | lr0: 0.0001
    - amp: True | cos_lr: True
    - workers: 8 | cache: True

--- 4.3 ประเมินผลหลังเทรน ---
[ ] ดู Confusion Matrix → หาคู่โรคที่สับสนกัน (เช่น BLB vs Brown Spot)
[ ] เช็ค Per-Class AP → ถ้าคลาสไหน AP ต่ำ ให้เพิ่มรูปหรือ Augmentation
[ ] บันทึกค่า: mAP@0.5, mAP@0.5:0.95, Precision, Recall, F1-Score
[ ] วัด Inference Time (ms/รูป) บนเครื่องเทรน
[ ] ปรับ Confidence Threshold จาก Precision-Recall Curve

    🔁 ถ้าผลไม่ดี (mAP < 0.7):
    - เพิ่ม epoch หรือปรับ lr0
    - ลองเพิ่ม cls_loss_gain หรือ focal loss สำหรับคลาสน้อย
    - เพิ่มรูปในคลาสที่ AP ต่ำ แล้วเทรนใหม่

--- 4.4 Export โมเดล ---
[ ] Export → ONNX format (สำหรับ deploy บน Jetson AGX Orin)
[ ] ทดสอบ Inference Speed จริงบน Jetson

--- 5.1 เตรียม Knowledge Base ---

    แหล่งข้อมูล: https://www.ricethailand.go.th/

[ ] สร้าง Prompt Template (ภาษาไทย):

     ตอบคำถามโดยอ้างอิงจาก Context ที่ให้เท่านั้น
     ถ้าไม่พบข้อมูลใน Context ให้ตอบว่าไม่ทราบ

 Phase 6: LINE + n8n Integration
 สถานะ: ยังไม่เริ่ม | กำหนดเสร็จ: สัปดาห์ที่ 4-5
====================================================================

--- 6.1 ตั้งค่า LINE ---
[ ] สมัคร LINE Official Account (https://manager.line.biz/)
[ ] เปิด LINE Messaging API → บันทึก Channel Access Token + Channel Secret
[ ] ออกแบบ Rich Menu (ปุ่ม: ส่งรูปวินิจฉัย / ถามเรื่องโรค / วิธีป้องกัน)

--- 6.2 ตั้งค่า n8n ---
[ ] ติดตั้ง n8n:
    - docker: docker run -it --rm -p 5678:5678 n8nio/n8n
    - หรือใช้ n8n.cloud (มี free tier)
[ ] สร้าง n8n Workflow:
    LINE Webhook
    ├── รับรูปภาพ → ส่งไป RT-DETR API → รับผลวินิจฉัย → LINE Reply
    └── รับข้อความ → RAG Pipeline → LLM สร้างคำตอบ → LINE Reply

--- 6.3 Deploy RT-DETR เป็น API ---
[ ] สร้าง REST API สำหรับ RT-DETR (FastAPI หรือ Flask)
    - Endpoint: POST /predict → รับรูป → ส่งกลับ class + confidence
    - Deploy บน Jetson AGX Orin หรือ Cloud Server

--- 6.4 กำหนด Confidence Threshold ---
[ ] ตั้งค่า logic ใน n8n Workflow:
    - confidence > 0.5  → แสดงผลวินิจฉัย (ชื่อโรค + สาเหตุ + วิธีรักษา)
    - confidence 0.3-0.5 → "ไม่แน่ใจ กรุณาถ่ายภาพใหม่ให้ชัดขึ้น"
    - confidence < 0.3  → "ไม่สามารถระบุรอยโรคได้ กรุณาลองใหม่"
    - ไม่พบ detection   → "ใบข้าวปกติ ไม่พบรอยโรค"

--- 7.1 Functional Testing (ตามตาราง 3-1) ---
[ ] Test 1: ส่งรูปโรคชัดเจน → ระบุชื่อโรค + วิธีรักษาถูกต้อง
[ ] Test 2: พิมพ์ "โรคไหม้รักษายังไง" → แสดงวิธีรักษา + สารเคมี
[ ] Test 3: ถาม "วิธีป้องกันโรคไหม้" → แสดงวิธีป้องกัน
[ ] Test 4: อธิบายอาการไม่ระบุชื่อโรค → ระบบวิเคราะห์ได้
[ ] Test 5: ถามอัตราส่วนสารเคมี → แสดงตัวเลขถูกต้อง
[ ] Test 6: ส่งรูปไม่ชัด → fallback "ถ่ายภาพใหม่"
[ ] Test 7: ถามนอกฐานข้อมูล → fallback "ไม่พบข้อมูล"
[ ] Test 8: พิมพ์ข้อความนอก intent → fallback "ไม่เข้าใจ"

--- 7.2 เก็บผลประเมิน ---
[ ] RT-DETR Evaluation → บันทึก mAP, Precision, Recall, F1-Score, Inference Time
[ ] RAG Evaluation (RAGAS) → บันทึก Context Precision, Faithfulness, Answer Relevance
[ ] User Satisfaction → แบบสอบถาม Likert Scale 5 ระดับ
    - กลุ่มตัวอย่าง: เกษตรกร/ผู้ใช้ทั่วไป จำนวน 30 คน
    - หัวข้อ: ความสะดวก, ความถูกต้อง, ความเร็ว, ความเป็นมิตร, ความพึงพอใจรวม
[ ] เขียนผลลัพธ์ทั้งหมดใส่บทที่ 4
