 Phase 3: Labeling + Data Augmentation
 สถานะ: ยังไม่เริ่ม | กำหนดเสร็จ: สัปดาห์ที่ 1-2
====================================================================


--- 3.1 ตั้งค่า Roboflow ---
[ ] สมัคร Roboflow (roboflow.com) → เลือกแผน Free/Starter
[ ] สร้าง Project → Object Detection → YOLO format
[ ] อัปโหลดรูปทั้งหมด (3,829 รูป | 6 คลาส)

--- 3.2 Labeling ---
[ ] ตี Bounding Box คลาสละ ~400-600 รูป (รวม ~2,400-3,600 รูป)
    คลาสที่ต้อง label (5 คลาสโรค):
    - bacterial_leaf_blight
    - brown_spot
    - leaf_blast
    - leaf_scald
    - sheath_blight

    ⚠️ กลยุทธ์ Healthy Class:
    - ไม่ต้องตี bbox (ไม่มีรอยโรคให้ตีกรอบ)
    - ใส่เป็น Negative Sample / Background Image ใน Train set
    - ในระบบจริง: ถ้า RT-DETR detect ไม่เจอ → ตอบ "ใบข้าวปกติ"

--- 3.3 จัดการ Class Imbalance ---
    Dataset ใหม่: ทุกคลาสใกล้เคียงกันมาก (~628–653 รูป)
    Class Imbalance ไม่ใช่ปัญหาหลักแล้ว ✅
    แต่ยังควรทำ Augmentation เพื่อเพิ่มปริมาณข้อมูลโดยรวม

[ ] ตั้งค่า Data Augmentation ใน Roboflow:
    - Rotation: ±15°
    - Brightness: ±20%
    - Blur: สุ่ม 0-2px
    - Flip: Horizontal
    - Crop: 0-10%
    (แนะนำ multiplier x3 สำหรับทุกคลาสเพื่อเพิ่มข้อมูลให้พอเทรน)

--- 3.4 Data Versioning (Roboflow) ---
[ ] เปิดใช้งาน Version ใน Roboflow หลังจาก Label เสร็จแต่ละรอบ
    - บันทึกเป็น Version (v1, v2, ...) ทุกครั้งที่มีการแก้ไข Bounding Box
    - ใส่หมายเหตุว่าแก้อะไร (เช่น "Fixed BLB bbox, added 50 new images")
[ ] Export เฉพาะ Version ที่ต้องการเสมอ (ไม่ export จาก draft)

--- 3.5 Export ---
[ ] Export → YOLO format → Split: Train 70% / Val 20% / Test 10%
[ ] ดาวน์โหลดและวางไฟล์ตามโครงสร้าง:
    data/raw/
    ├── train/images/  +  train/labels/
    ├── val/images/    +  val/labels/
    └── test/images/   +  test/labels/

 Phase 4: Train + Evaluate RT-DETR
 สถานะ: ยังไม่เริ่ม | กำหนดเสร็จ: สัปดาห์ที่ 2-3
====================================================================

--- 4.1 เตรียมสภาพแวดล้อม ---
[ ] pip install ultralytics
[ ] ตรวจสอบ CUDA: python -c "import torch; print(torch.cuda.is_available())"
[ ] ยืนยัน dataset.yaml path ถูกต้อง (ดู Project/dataset.yaml)

--- 4.2 เทรนโมเดล ---
[ ] รัน Project/train_rtdetr.py
    พารามิเตอร์สำคัญ:
    - Model: RT-DETR-L (rtdetr-l.pt, pretrained COCO)
    - imgsz: 640 | batch: 8 (ปรับเป็น 16 ถ้า VRAM พอ)
    - epochs: 100 | patience: 15 (Early Stopping)
    - optimizer: AdamW | lr0: 0.0001
    - amp: True | cos_lr: True
    - workers: 8 | cache: True

--- 4.3 ประเมินผลหลังเทรน ---
[ ] ดู Confusion Matrix → หาคู่โรคที่สับสนกัน (เช่น BLB vs Brown Spot)
[ ] เช็ค Per-Class AP → ถ้าคลาสไหน AP ต่ำ ให้เพิ่มรูปหรือ Augmentation
[ ] บันทึกค่า: mAP@0.5, mAP@0.5:0.95, Precision, Recall, F1-Score
[ ] วัด Inference Time (ms/รูป) บนเครื่องเทรน
[ ] ปรับ Confidence Threshold จาก Precision-Recall Curve

    🔁 ถ้าผลไม่ดี (mAP < 0.7):
    - เพิ่ม epoch หรือปรับ lr0
    - ลองเพิ่ม cls_loss_gain หรือ focal loss สำหรับคลาสน้อย
    - เพิ่มรูปในคลาสที่ AP ต่ำ แล้วเทรนใหม่

--- 4.4 บันทึก Checkpoint และ Experiment ---
[ ] ผลเทรนจะอยู่ที่ rice_disease_rtdetr/exp1/ (ตาม train_rtdetr.py)
    - best.pt  → โมเดลที่ดีที่สุด (ใช้งานจริง)
    - last.pt  → checkpoint ล่าสุด (ใช้ resume ถ้าเทรนหยุดกลางคัน)
[ ] บันทึกผลแต่ละ Experiment ลงใน CSV ด้วยมือ:
    | exp | epochs | imgsz | batch | mAP@0.5 | mAP@0.5:0.95 | หมายเหตุ |
    - ถ้าต้องการ Tracking อัตโนมัติ: เพิ่ม project= และ name= ใน train_rtdetr.py
[ ] เก็บ best.pt ของแต่ละ Experiment ไว้แยกโฟลเดอร์ (อย่า overwrite)

--- 4.5 Export โมเดล ---
[ ] Export → ONNX format (สำหรับ deploy บน Jetson AGX Orin)
[ ] ทดสอบ Inference Speed จริงบน Jetson

--- 6.2 ตั้งค่า n8n ---
[ ] ติดตั้ง n8n:
    - docker: docker run -it --rm -p 5678:5678 n8nio/n8n
    - หรือใช้ n8n.cloud (มี free tier)
[ ] สร้าง n8n Workflow:
    LINE Webhook
    ├── รับรูปภาพ → ส่งไป RT-DETR API → รับผลวินิจฉัย → LINE Reply
    └── รับข้อความ → RAG Pipeline → LLM สร้างคำตอบ → LINE Reply

--- 6.3 Deploy RT-DETR เป็น API ---
[ ] สร้าง REST API สำหรับ RT-DETR (FastAPI หรือ Flask)
    - Endpoint: POST /predict → รับรูป → ส่งกลับ class + confidence
    - Deploy บน Jetson AGX Orin หรือ Cloud Server

--- 6.4 กำหนด Confidence Threshold ---
[ ] ตั้งค่า logic ใน n8n Workflow:
    - confidence > 0.5  → แสดงผลวินิจฉัย (ชื่อโรค + สาเหตุ + วิธีรักษา)
    - confidence 0.3-0.5 → "ไม่แน่ใจ กรุณาถ่ายภาพใหม่ให้ชัดขึ้น"
    - confidence < 0.3  → "ไม่สามารถระบุรอยโรคได้ กรุณาลองใหม่"
    - ไม่พบ detection   → "ใบข้าวปกติ ไม่พบรอยโรค"
