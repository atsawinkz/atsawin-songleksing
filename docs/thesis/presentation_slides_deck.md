## 🖥️ สไลด์ที่ 2: ที่มา ความสำคัญ และปัญหาการสูญเสียผลผลิตข้าวไทย (Problem Statement)

* **ความสำคัญเชิงเศรษฐกิจ:**
  - ข้าวเป็นพืชเศรษฐกิจอันดับหนึ่งของประเทศไทย มีพื้นที่เพาะปลูกกว่า 60 ล้านไร่ เกษตรกรกว่า 4.6 ล้านครัวเรือน
* **ปัญหาสำคัญของการทำนา (Pain Points):**
  - **การสูญเสียผลผลิต 15–30% ต่อปี:** เกิดจากการระบาดของโรคข้าวสำคัญ 5 ชนิด เช่น โรคขอบใบแห้ง, ใบไหม้, ใบจุดสีน้ำตาล, ใบขอบกาบแห้ง และกาบใบแห้ง
  - **การขาดแคลนผู้เชี่ยวชาญในแปลงนา:** เจ้าหน้าที่เกษตรไม่สามารถเข้าถึงพื้นที่ได้ทั่วถึงทุกแปลง เกษตรกรต้องวินิจฉัยโรคด้วยตนเองจากสายตา
  - **ความสับสนทางสัณฐานวิทยาของโรค:** โรคข้าวหลายชนิดมีอาการคล้ายคลึงกันมาก (เช่น โรคขอบใบแห้ง มีริ้วแผลคล้ายโรคใบขอบกาบแห้ง) ทำให้เกษตรกรซื้อสารเคมีผิดประเภท
  - **การใช้สารเคมีเกินขนาด (Overuse & Misuse):** ทำให้เกิดเชื้อดื้อยา ต้นทุนการผลิตพุ่งสูง ดินและแหล่งน้ำปนเปื้อนสารพิษ และผลผลิตข้าวไม่ผ่านเกณฑ์การส่งออก
* **ช่องว่างทางเทคโนโลยี (Technology Gap):**
  - โมเดลตรวจจับในอดีตมักช้าเกินไป ไม่รองรับสภาพแวดล้อมแสงจริงในแปลงนา และระบบถาม-ตอบแบบ LLM ดั้งเดิมมักเกิดปัญหา "ภาพหลอน (Hallucination)" แนะนำสารเคมีหรืออัตราส่วนผสมที่ผิดพลาด
* **🎙️ Script ผู้บรรยาย:**
  > *"ข้าวไทยเป็นกระดูกสันหลังของชาติ แต่ในทุกๆ ปี เกษตรกรต้องสูญเสียผลผลิตไปมากถึง 15–30% จากโรคพืช ปัญหาหลักไม่ได้เกิดจากการไม่มียารักษา แต่เกิดจากการวินิจฉัยโรคผิดพลาดครับ รอยโรคของข้าวบางชนิดมีหน้าตาคล้ายกันมาก เช่น โรคขอบใบแห้งที่เกิดจากแบคทีเรีย กับโรคใบขอบกาบแห้งที่เกิดจากเชื้อรา หากเกษตรกรซื้อยาผิดกลุ่ม นอกจากจะรักษาไม่หายแล้ว ยังทำให้เชื้อดื้อยาและเสียเงินโดยเปล่าประโยชน์ ยิ่งไปกว่านั้น ระบบ AI ทั่วไปในปัจจุบันหากไม่มีการควบคุมบริบท จะเกิดอาการภาพหลอน แนะนำชื่อสารเคมีหรืออัตราส่วนมั่ว ซึ่งเป็นอันตรายต่อแปลงนา โครงงานนี้จึงเกิดขึ้นเพื่อปิดช่องว่างเหล่านี้อย่างเด็ดขาดครับ"*

## 🖥️ สไลด์ที่ 4: สถาปัตยกรรมระบบรวม 4 ระดับ (End-to-End System Architecture)

* **ผังสถาปัตยกรรม 4-Tier Architecture:**

```
[ Tier 1: Presentation Layer ]
  └─ เกษตรกรใช้งานผ่าน LINE Application (ส่งภาพถ่าย / พิมพ์ข้อความสอบถาม)
        │ (HTTPS Webhook ผ่าน LINE Messaging API & ngrok)
        ▼
[ Tier 2: Orchestration Layer ]
  └─ n8n Automation Router (รันบน Docker Container)
        ├─ ตรวจสอบ Intent (Image Event vs Text Event)
        └─ ควบคุมการไหลของข้อมูลและประกอบร่าง LINE Flex Message
        │
        ├── [กรณีเป็นภาพถ่าย] ───────────────┐
        │                                    ▼
[ Tier 3: Vision Intelligence Layer ]  [ Tier 4: Knowledge & RAG Layer ]
  ├─ FastAPI Inference Server            ├─ Pinecone Vector DB (Dense Embeddings)
  ├─ RT-DETR-L v5 (ONNX FP16)            ├─ PyThaiNLP Tokenizer (Sparse BM25)
  ├─ ตรวจจับรอยโรคใน 6.8 ms             ├─ Alpha Blending Engine (α = 0.7)
  └─ ส่ง BBox + ชื่อโรค + Conf ให้ RAG ──┘  └─ Google Gemini 2.5 Flash Generator
```

* **ลำดับการประมวลผล (End-to-End Sequence Flow):**
  1. เกษตรกรส่งภาพถ่ายใบข้าวผ่าน LINE OA
  2. n8n ดึงภาพ Binary ผ่าน LINE Messaging API ส่งต่อไปยัง FastAPI `/predict`
  3. RT-DETR Model ประมวลผลและส่งผลลัพธ์: ชื่อโรค, ความมั่นใจ, และพิกัด Bounding Box
  4. n8n ส่งชื่อโรคพร้อมบริบทไปยัง RAG API `/rag_query` เพื่อดึงข้อมูลสารเคมีและวิธีปฏิบัติตามมาตรฐานกรมการข้าว
  5. n8n นำผลลัพธ์ประกอบร่างเป็น LINE Flex Message ส่งกลับเข้าหน้าแชทของเกษตรกรภายใน **1.68 วินาที**
* **🎙️ Script ผู้บรรยาย:**
  > *"ในภาพนี้แสดงสถาปัตยกรรมระบบรวมแบบ 4 ระดับครับ เริ่มจาก Presentation Layer คือ LINE ที่เกษตรกรคุ้นเคย ส่งข้อมูลผ่านท่อ HTTPS เข้าสู่ Orchestration Layer คือ n8n บน Docker เพื่อคัดแยกประเภทข้อมูล หากเป็นภาพถ่ายจะถูกส่งเข้า Vision Layer คือ RT-DETR v5 บน FastAPI ซึ่งใช้เวลาตรวจจับเพียง 6.8 มิลลิวินาที จากนั้นระบบจะส่งชื่อโรคต่อไปยัง Knowledge Layer คือ Hybrid RAG เพื่อดึงแนวทางการรักษาที่ถูกต้องตามหลักวิชาการ แล้ว n8n จะประกอบข้อมูลทั้งหมดเป็น Flex Message ตอบกลับสู่หน้าจอเกษตรกรทันทีครับ"*

## 🖥️ สไลด์ที่ 6: การปฏิวัติฉลากข้อมูลด้วย Data-Centric AI (Annotation Refinement Breakthrough)

* **วิกฤตคอขวดของโมเดลรุ่นแรก (The Bottleneck Crisis):**
  - ในการฝึกฝนโมเดลเวอร์ชันแรก โรคขอบใบแห้ง (Bacterial Leaf Blight: BLB) ได้คะแนนความแม่นยำต่ำผิดปกติ ($mAP@0.5 = 7.42\%$)
  - แม้จะพยายามเปลี่ยนสถาปัตยกรรมโมเดลและปรับ Hyperparameters อย่างไร คะแนนก็ไม่กระเตื้อง
* **การวิเคราะห์ข้อผิดพลาดเชิงลึก (Deep Error Analysis):**
  - ผู้วิจัยลงไปตรวจสอบฉลากข้อมูลรายภาพ และพบปัญหา **Annotation Fragmentation**:
  - รอยโรคขอบใบแห้งที่มีลักษณะเป็นแผลเดี่ยวทอดยาวตามขอบใบ กลับถูกผู้ติดฉลากเดิมตีกรอบซอยย่อยแตกกระจายเป็นกล่องเล็กๆ ซ้อนทับกันมากถึง **5,922 กล่อง**
  - โมเดลสับสนในการคำนวณ Intersection-over-Union (IoU) และสร้าง False Positive มหาศาล
* **การแก้ไขตามกระบวนทัศน์ Data-Centric AI:**
  - ผู้วิจัยทำการ Re-labeling ชุดข้อมูลใหม่ทั้งหมด โดยยุบรวมกรอบย่อยให้เป็นกรอบรอยโรคต่อเนื่องตามสัณฐานวิทยาจริง (**Continuous Morphological Bounding Box**)
  - ลดจำนวนกรอบที่ซ้ำซ้อนจาก **5,922 กล่อง เหลือเพียง 1,863 กล่อง** (ลดขยะข้อมูลลง 68.5%)
* **ผลลัพธ์เชิงประจักษ์:**
  - คะแนน $mAP@0.5$ ของโรคขอบใบแห้งพุ่งทะยานจาก **`7.42%` สู่ `69.50%` (เพิ่มขึ้นทันที +62.1% !)**
* **🎙️ Script ผู้บรรยาย:**
  > *"นี่คือจุดเปลี่ยนสำคัญที่สุดของงานวิจัยชิ้นนี้ครับ ในช่วงแรกของการทดลอง โมเดลของเราล้มเหลวอย่างสิ้นเชิงกับโรคขอบใบแห้ง โดยได้คะแนนเพียง 7.4% เมื่อเราวิเคราะห์ลึกลงไป เราพบว่าผู้ติดฉลากข้อมูลเดิมได้ตีกรอบแผลยาวแผลเดียว แตกออกเป็นกล่องย่อยๆ ซ้อนกันถึงเกือบ 6,000 กล่อง เราจึงใช้แนวทาง Data-Centric AI แก้ไขกรอบทั้งหมดใหม่ให้ครอบคลุมตามสัณฐานจริงเหลือ 1,863 กล่อง ส่งผลให้คะแนนความแม่นยำของโรคขอบใบแห้งพุ่งทะยานขึ้นถึง 62.1% พิสูจน์ให้เห็นว่า คุณภาพของข้อมูล มีผลต่อความฉลาดของ AI มากกว่าการจูนโมเดลครับ"*

## 🖥️ สไลด์ที่ 9: การทดลอง Ablation Study: ปัญหา Green-on-Green และความล้มเหลวของ SOD

* **สมมติฐานการวิจัย (Research Hypothesis):**
  - *"การตัดฉากหลังแปลงนา (ดิน น้ำ วัชพืช) ให้กลายเป็นสีดำสนิทล่วงหน้า จะช่วยลดสัญญาณรบกวนและเพิ่มความแม่นยำของโมเดล Object Detection ได้จริงหรือไม่?"*
* **ความล้มเหลวของการตัดพื้นหลังอัตโนมัติดั้งเดิม (Salient Object Detection - SOD):**
  - เมื่อนำโมเดลตัดฉากหลังยอดนิยม (เช่น U-2-Net / SOD) มาประมวลผลภาพใบข้าวในแปลงนา
  - **เกิดปรากฏการณ์ภาพกลายเป็น "จอดำสนิท" สูงถึง `43.8%` (155 จาก 354 ภาพ)** เนื้อใบข้าวถูกลบทิ้งไปทั้งหมด
* **สาเหตุทางฟิสิกส์และคอมพิวเตอร์วิทัศน์:**
  1. **Green-on-Green Contrast Failure:** สีเขียวของใบข้าวกลืนไปกับสีเขียวของต้นข้าวเบื้องหลังและวัชพืช ทำให้ AI หาขอบวัตถุไม่เจอ
  2. **Edge-to-Edge Macro Geometry:** ภาพถ่ายใบข้าวระยะใกล้ (Macro Shot) ปลายใบจะทอดยาวทะลุกรอบภาพ ไม่มีรูปทรงปิดล้อม (Closed Contour) อัลกอริทึมจึงตีความผิดว่าเป็น Background ทั้งหมดแล้วถมดำทับ
* **🎙️ Script ผู้บรรยาย:**
  > *"ในงานวิจัยนี้ เราไม่ได้หยุดแค่การเทรนโมเดล แต่เราตั้งคำถามวิจัยที่ลึกซึ้งว่า ถ้าเราตัดฉากหลังแปลงนาออกให้เหลือแต่ใบไม้เพียวๆ โมเดลจะฉลาดขึ้นหรือไม่ ในขั้นแรกเราทดลองใช้โมเดลตัดฉากหลังอัตโนมัติทั่วไป ปรากฏว่าล้มเหลวอย่างสิ้นเชิงครับ มีภาพกลายเป็นจอดำมืดสนิทถึง 43.8% สาเหตุเพราะสีเขียวของใบข้าวกลืนไปกับแปลงนา (Green-on-Green) และใบข้าวพาดทะลุขอบจอจน AI มองไม่เห็นขอบเขตวัตถุ จึงลบเนื้อใบข้าวจนหายไปเกือบครึ่งหนึ่งของชุดข้อมูลครับ"*

## 🖥️ สไลด์ที่ 10: โซลูชันใหม่: MobileSAM + Enclosing BBox + Safety Guardrail 2%

* **การออกแบบไปป์ไลน์ตัดพื้นหลังใหม่ด้วย Foundation Model:**
  - คณะผู้วิจัยเปลี่ยนมาใช้ **Meta MobileSAM** (โมเดล Segment Anything ขนาดเล็กที่รันได้เร็ว) ผสานกับระเบียบวิธี Prompting ขั้นสูง:
* **3 กลไกนวัตกรรมในการสกัดพื้นหลัง:**
  1. **Enclosing Bounding Box Prompting:** สกัดกรอบพิกัดครอบคลุมรอยโรคทั้งหมด ป้อนเป็น Guidance Prompt ให้ MobileSAM ล็อคเป้าและตัดเฉพาะเนื้อใบไม้ที่เกี่ยวข้อง
  2. **Morphological Dilation:** ขยายขอบ Mask ออกไปเล็กน้อยเพื่อป้องกันไม่ให้ขอบแผลถูกตัดขาด
  3. **Adaptive Safety Guardrail ($\theta = 0.02$):** ตรวจสอบพิกเซลที่รอดชีวิตหลังการตัด หากสัดส่วนพิกเซลใบไม้น้อยกว่า 2% ของภาพ ระบบจะตัดสลับกลับไปใช้ภาพต้นฉบับ (**Fallback to Original**) ทันทีอัตโนมัติ
* **ผลลัพธ์การเตรียมข้อมูลตัดฉากหลัง:**
  - ประมวลผลตัดฉากหลังสำเร็จยอดเยี่ยม **75.14% (266 ภาพ)**
  - Guardrail ทำงาน Fallback ภาพที่มีความเสี่ยงอย่างปลอดภัย **24.86% (88 ภาพ)**
  - **กำจัดปัญหาภาพจอดำสนิทได้ 100%** พร้อมนำไปใช้เทรนโมเดลเปรียบเทียบ
* **🎙️ Script ผู้บรรยาย:**
  > *"เพื่อแก้ปัญหาจอดำ เราได้ออกแบบไปป์ไลน์ใหม่โดยนำ Meta MobileSAM มาทำงานร่วมกับระบบความปลอดภัยที่เราพัฒนาขึ้น เรียกว่า Adaptive Safety Guardrail โดยเราป้อนกรอบรอยโรคเข้าไปนำทาง SAM และตั้งเกณฑ์ว่า ถ้าภาพไหนถูกตัดแล้วเหลือเนื้อใบไม้น้อยกว่า 2% ให้ระบบ Fallback กลับไปใช้ภาพเดิมทันที ผลปรากฏว่าระบบสามารถตัดฉากหลังได้สำเร็จ 75% และ Fallback อย่างปลอดภัย 25% โดยไม่มีภาพจอดำหลุดรอดไปทำลายการเรียนรู้ของโมเดลเลยแม้แต่ภาพเดียวครับ"*

  - **Micro-lesions (แผลจุดเล็กจิ๋ว):** โรคใบจุดสีน้ำตาลคะแนน **ดิ่งฮวบลงถึง -15.19%** เนื่องจากจุดแผลขนาดเล็กต้องการ "สัญญาณบริบทของเนื้อใบสีเขียวรอบแผล (Context)" เมื่อฉากหลังกลายเป็นสีดำ โมเดลสับสนคิดว่าจุดสีน้ำตาลเป็นสัญญาณรบกวน (Noise)

## 🖥️ สไลด์ที่ 13: การออกแบบฐานความรู้โรคข้าวและการจัดการ Chunk (Knowledge Base Strategy)

* **แหล่งที่มาขององค์ความรู้ (Knowledge Source):**
  - รวบรวมจากเอกสารวิชาการมาตรฐานของ **กรมการข้าว กระทรวงเกษตรและสหกรณ์**
  - ครอบคลุม 5 มิติ: ลักษณะอาการ, เชื้อสาเหตุ, วงจรการระบาด, การใช้สารเคมีที่ถูกต้องตามกฎหมาย, และวิธีเขตกรรมป้องกัน
* **กลยุทธ์การหั่นข้อมูล (Chunking Strategy):**
  - ค้นพบจุดสมดุล (Sweet Spot) ที่ **Chunk Size = 1,500 ตัวอักษร** และ **Chunk Overlap = 300 ตัวอักษร**
  - ป้องกันปัญหา *Context Fragmentation* (บริบทขาดหาย) และ *Lost in the Middle* (ข้อมูลยาวเกินไปจน AI ตาพร่า)
* **2 เทคนิคขั้นสูงในการยกระดับคุณภาพข้อมูล:**
  1. **Context Enrichment:** แปะหัวกระดาษกำกับชื่อโรค (Header Prefix) ในทุก Chunk เช่น `[โรคขอบใบแห้ง - การรักษาด้วยสารเคมี]` เพื่อล็อกบริบทให้โมเดลภาษา
  2. **Metadata Filtering:** ระบบตรวจจับชื่อโรคจากภาพถ่ายจะนำชื่อโรคไปทำ Metadata Filter ล็อกเป้าหมายการค้นหาใน Pinecone ตัดเอกสารของโรคอื่นทิ้ง 100% ป้องกันการดึงข้อมูลปนเปื้อน
* **🎙️ Script ผู้บรรยาย:**
  > *"ในส่วนของสมองการให้คำปรึกษา เราสร้างฐานความรู้มาตรฐานจากเอกสารของกรมการข้าว โดยเราค้นพบจุดที่เหมาะสมที่สุดในการแบ่งเนื้อหา คือก้อนละ 1,500 ตัวอักษร และเหลื่อมซ้อนกัน 300 ตัวอักษร เพื่อไม่ให้ข้อความสำคัญถูกตัดขาดตอน และเรายังใช้เทคนิค Context Enrichment แปะป้ายชื่อโรคกำกับไว้ที่หัวเอกสารทุกแผ่น ร่วมกับ Metadata Filtering เพื่อล็อกเป้าให้ระบบค้นหาเฉพาะโรคที่ตรวจพบเท่านั้น ตัดเสียงรบกวนจากโรคอื่นออกอย่างสมบูรณ์ครับ"*

## 🖥️ สไลด์ที่ 23: ข้อจำกัดและแนวทางการพัฒนาต่อยอดในอนาคต (Limitations & Future Roadmap)

* **ข้อจำกัดของงานวิจัยในปัจจุบัน (Current Limitations):**
  - **การจำกัดชนิดโรค:** ครอบคลุม 5 โรคสำคัญที่เกิดจากเชื้อราและแบคทีเรีย (ยังไม่ครอบคลุมโรคไวรัส เช่น โรคใบสีส้ม และศัตรูพืชจำพวกแมลง)
  - **การพึ่งพาคลาวด์:** สถาปัตยกรรมส่วน LLM ยังต้องเชื่อมต่ออินเทอร์เน็ตในการประมวลผลคำตอบ
  - **สภาพแสงสุดขั้ว:** ประสิทธิภาพอาจลดลงในสภาพแสงน้อยเวลากลางคืน หรือมีเงาสะท้อนน้ำรุนแรง
* **แผนที่นำทางการพัฒนาต่อยอด 4 ทิศทาง (Future Roadmap):**
  1. **Edge Quantization (TensorRT INT8):** ทำการบีบอัดโมเดลเพื่อรันบนบอร์ด **NVIDIA Jetson AGX Orin** ให้มีความเร็วสูงขึ้นและกินไฟต่ำ
  2. **Smart Agriculture Camera & Drone (UAV):** ติดตั้งกล้อง Edge AI บนเสากลางแปลงนา และเชื่อมต่อโดรนการเกษตรบินสำรวจแปลงนาแบบอัตโนมัติ
  3. **Offline Small Language Model (SLM):** นำโมเดลภาษาขนาดเล็ก (เช่น LLaMA-3-8B-Thai หรือ Gemma-2B) มารันบนบอร์ด Jetson เพื่อตอบคำถามแบบออฟไลน์ในพื้นที่ไร้สัญญาณเน็ต
  4. **Active Learning Feedback Loop:** เพิ่มปุ่มให้เกษตรกรส่งภาพที่วินิจฉัยผิดกลับมารีเทรนโมเดลใหม่โดยอัตโนมัติ
* **🎙️ Script ผู้บรรยาย:**
  > *"สำหรับข้อจำกัดและทิศทางในอนาคต ปัจจุบันระบบครอบคลุมโรคหลัก 5 ชนิด ในอนาคตเราสามารถต่อยอดขยายผลได้อีก 4 มิติครับ คือ 1) แปลงโมเดลเป็น TensorRT INT8 เพื่อติดตั้งบนบอร์ด Jetson AGX Orin ให้กินไฟต่ำ 2) เชื่อมต่อเข้ากับโดรนการเกษตรหรือกล้องเสากลางนาเพื่อบินตรวจโรคอัตโนมัติ 3) พัฒนาโมเดลภาษาขนาดเล็กติดตั้งในเครื่องเพื่อให้บริการในพื้นที่ที่ไม่มีสัญญาณอินเทอร์เน็ต และ 4) พัฒนาระบบ Continuous Active Learning ให้โมเดลฉลาดขึ้นเรื่อยๆ จากภาพถ่ายของเกษตรกรครับ"*
