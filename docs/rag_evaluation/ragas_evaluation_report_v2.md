# รายงานประเมินผลระบบ RAG (RAGAS Evaluation Report) - Version 2 (TOP_K = 5)

**วันที่ประเมิน:** 6 กรกฎาคม 2026

**จำนวนข้อสอบ:** 70 ข้อ (รันเสร็จสมบูรณ์ 100%)
**โมเดลที่ใช้ประเมิน:** DeepSeek-V4-Flash-Free (ผู้ให้คะแนน) / Gemini-3.1-Flash-Lite (ผู้ทำข้อสอบ)

หลังจากที่เราได้วิเคราะห์จุดอ่อนใน Version 1 และทดลองใช้มาตรการ "Quick Win" โดยการเพิ่มค่า `TOP_K` เป็น 5 ก้อน (Chunks) นี่คือผลลัพธ์การประเมินรอบใหม่ที่พิสูจน์ให้เห็นถึงความเปลี่ยนแปลงครับ

## 🔍 2. บทวิเคราะห์เจาะลึกผลลัพธ์ (Diagnosis)

การเพิ่ม Top-K เป็น 5 ได้ส่งผลกระทบในทิศทางที่เป็นบวกต่อระบบอย่างชัดเจน โดยสามารถสรุปประเด็นสำคัญได้ดังนี้:

### 👍 2.1 สมมติฐานถูกต้อง: Context Recall ดีขึ้นอย่างเห็นได้ชัด (+6.09%)
การที่เราสั่งให้ระบบคว้าข้อมูลกลับมา 5 ย่อหน้า แทนที่จะเป็น 3 ย่อหน้า ช่วยแก้ปัญหา "ข้อมูลตกหล่น" ได้จริง ส่งผลให้คะแนนความครอบคลุมเนื้อหา (Context Recall) ขยับขึ้นจาก 17.7% เป็นเกือบ 24% ซึ่งถือเป็นก้าวแรกที่ดีมาก

### 👍 2.2 ผลกระทบเชิงบวกต่อเนื่อง: ตอบคำถามได้ตรงประเด็นขึ้น
เมื่อ LLM ได้รับข้อมูลที่ครอบคลุมมากขึ้น มันก็สามารถประกอบร่างคำตอบได้สมบูรณ์และตรงกับคำถามมากขึ้น ส่งผลให้คะแนน **Answer Relevancy** ขยับผ่านเส้น 50% เป็นที่เรียบร้อย

### ⚖️ 2.3 Trade-off ที่ยอมรับได้: Faithfulness แกว่งเล็กน้อย
การป้อนข้อมูลให้ LLM เยอะขึ้นจาก 3 เป็น 5 ก้อน หมายถึงมีตัวอักษรให้ LLM ต้องประมวลผลมากขึ้น อาจทำให้มีจังหวะที่ LLM ดึงข้อมูลมาผสมกันแล้วหลุดกรอบไปบ้างเล็กน้อย ทำให้ Faithfulness ลดลงเพียงเศษเสี้ยว (0.7%) ซึ่งถือว่าเป็น Trade-off (ได้อย่างเสียอย่าง) ที่คุ้มค่ามาก เพราะคะแนนยังเกาะกลุ่มอยู่ที่เกณฑ์ 70% ซึ่งถือว่าปลอดภัยและไม่มั่ว

## 🛠️ 3. ข้อเสนอแนะสำหรับเฟสถัดไป (Next Steps)

ถึงแม้ "Quick Win" รอบนี้จะทำให้กราฟเชิดหัวขึ้น แต่ Context Recall ที่ 23.8% ก็ยังถือว่าน้อยเกินกว่าจะนำไปใช้งานจริงกับเกษตรกร (Production) สิ่งที่ผลลัพธ์ V2 บอกเราคือ **"การเพิ่มจำนวนก้อนข้อมูล (Top-K) ช่วยได้จริง แต่อาจจะสุดทางของ Vector Search เพียวๆ แล้ว"**

ดังนั้น เพื่อยกระดับคะแนนให้ทะลุ 50-70% ให้ได้ในอนาคต เราต้องใช้ "ยาแรง" มากขึ้น:
1. **เปลี่ยนมาใช้ Hybrid Search อย่างเต็มรูปแบบ:** นำการค้นหาแบบ Keyword (BM25) มาผสานกับ Vector Search เพื่อจับคำเฉพาะ (ชื่อโรค, ชื่อพันธุ์ข้าว, ตัวยาเคมี) ไม่ให้หลุดรอด
2. **ปรับกลยุทธ์การหั่นไฟล์ (Re-Chunking):** โครงสร้างไฟล์ Markdown ปัจจุบันอาจถูกตัดท่อนแบบไม่เกยกัน ทำให้บริบททางเทคนิคขาดหาย ต้องลองปรับขนาด Chunk Size และ Overlap ใหม่
3. **ติดแท็ก Metadata อย่างเป็นระบบ:** ระบุหมวดหมู่โรคในแต่ละ Chunk ล่วงหน้า เพื่อจำกัดวงค้นหาให้แคบและแม่นยำที่สุด
