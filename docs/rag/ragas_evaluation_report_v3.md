## 🔍 2. บทวิเคราะห์เจาะลึกผลลัพธ์ (Diagnosis)

จากการทดลองดันค่า Top-K ขึ้นเป็น 7 ก้อน เราได้ข้อสรุปที่ชัดเจนมากในเชิงสถาปัตยกรรมระบบ ดังนี้:

### ⚠️ 2.1 ถึงจุดอิ่มตัวของการดึงข้อมูล (Diminishing Returns)
คะแนน **Context Recall** หยุดนิ่งอยู่ที่ **23.76%** ซึ่งแทบไม่ต่างจากการตั้งค่า Top-K=5 เลย (23.80%) สิ่งนี้เป็นเครื่องพิสูจน์ตามหลักการว่า **"ถ้า Vector Search หาความหมายที่ตรงกันไม่เจอใน 5 ก้อนแรก การดึงก้อนที่ 6 และ 7 มาก็ไม่ได้ช่วยอะไร เพราะมันคือข้อมูลที่ไม่เกี่ยวข้อง (Noise) ไปแล้ว"** การเพิ่ม Top-K ไปมากกว่านี้จึงเป็นการสิ้นเปลืองโควตา Token โดยเปล่าประโยชน์

### 👍 2.2 LLM จัดการกับ Noise ได้ดี (Robustness)
แม้เราจะส่งข้อมูลให้ LLM มากถึง 7 ก้อน (ซึ่งย่อมมีข้อมูลขยะปนไปบ้าง) แต่คะแนน **Faithfulness** ก็ไม่ได้ตกลงไป แถมยังทรงตัวอยู่ที่ **69.7%** แปลว่าโมเดล Gemini-3.1-Flash-Lite ที่เราเลือกใช้ มีความสามารถในการคัดกรองเนื้อหาและไม่แต่งเรื่องมั่ว (Hallucination) ได้ดีมาก 

### 👍 2.3 การตอบคำถามที่สมบูรณ์ขึ้นเล็กน้อย
**Answer Relevancy** ขยับขึ้นมาแตะ **53.0%** แสดงให้เห็นว่า เมื่อมีเนื้อหาประกอบเยอะขึ้น LLM สามารถเรียบเรียงคำตอบได้ครอบคลุมประเด็นคำถามมากขึ้นเล็กน้อย

## 🛠️ 3. ข้อสรุปและทิศทางในอนาคต (Next Steps)

ผลการทดลองใน Version 3 นี้เป็นจุดตัดที่ทำให้เราตัดสินใจทางสถาปัตยกรรมได้อย่างเด็ดขาดว่า **"เราไม่สามารถใช้วิธีแก้ปัญหาแบบ Quick Win (การเพิ่ม Top-K) ได้อีกต่อไป"** 

เพื่อแก้ปัญหา Context Recall ที่จมอยู่ที่ 24% เราจำเป็นต้องรื้อโครงสร้างการจัดเก็บข้อมูลใหม่เมื่อเข้าสู่ช่วง Tuning:
1. **แก้ปัญหาที่ต้นเหตุ (Re-Chunking):** เราต้องกลับไปดูไฟล์ Markdown ว่าถูกตัดแบ่งอย่างไรให้บริบทขาดหาย ต้องเพิ่ม Overlap ให้ข้อความเชื่อมต่อกัน
2. **Hybrid Search เป็นสิ่งจำเป็น:** ต้องนำ Keyword Search (BM25) เข้ามาช่วย Vector Search เพื่อจับคำเฉพาะ (ชื่อโรค, ตัวยา) เพราะ Vector Search เพียวๆ ได้แสดงขีดจำกัดของมันออกมาแล้วในรอบนี้
3. **ติด Metadata Filtering:** บังคับให้ระบบค้นหาเฉพาะในหมวดหมู่โรคที่เกี่ยวข้อง เพื่อตัด Noise ออกตั้งแต่แรก

**🎯 บทสรุป:** 
การทดลองครบ 3 ระดับ (K=3, 5, 7) ทำให้โครงงานนี้มีความสมบูรณ์ในแง่ของการวิจัยและเปรียบเทียบพารามิเตอร์ ตอนนี้เราเข้าใจข้อจำกัดของระบบ RAG ปัจจุบันอย่างทะลุปรุโปร่งแล้ว พร้อมสำหรับการนำระบบไปเชื่อมต่อกับช่องทางใช้งานจริง (LINE Bot) ต่อไปครับ
