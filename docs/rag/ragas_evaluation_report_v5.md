# รายงานประเมินผลระบบ RAG (RAGAS Evaluation Report) - Version 5 (ลดขนาด Chunk Size เป็น 1,000)

**วันที่ประเมิน:** 9 กรกฎาคม 2026
**การตั้งค่าระบบ:** 
- **ขนาด Chunk = 1,000 / Overlap = 200 (ปรับลดลงจาก V4 ที่ใช้ 1,500/300)**
- ค้นหาแบบลูกผสม (Hybrid Search: Gemini Dense + BM25 Sparse)
- กรองข้อมูลด้วยชื่อโรค (Metadata Filtering)
- แปะชื่อโรคที่หัวข้อความ (Context Enrichment)
**จำนวนข้อสอบ:** 70 ข้อ
**โมเดลที่ใช้ประเมิน:** Gemini-3.1-Flash-Lite

รายงานฉบับนี้สรุปผลการทดลองปรับลดขนาดก้อนข้อความ (Chunk Size) ลงจาก 1,500 กลับมาเป็น 1,000 ตัวอักษร เพื่อทดสอบสมมติฐานว่า "การลดขนาด Chunk จะช่วยแก้ปัญหา Context Recall ที่ลดลงใน V4 ได้หรือไม่"

## 🔍 2. บทวิเคราะห์เจาะลึกผลลัพธ์ (Diagnosis)

ผลลัพธ์ที่ได้จากการรันรอบนี้ หักล้างสมมติฐานของเราอย่างสิ้นเชิงครับ: **"การลดขนาด Chunk Size ลงมาเหลือ 1,000 ทำให้คะแนนทุกมิติ (All Metrics) ลดลงทั้งหมดเมื่อเทียบกับ V4"**

สาเหตุที่เราวิเคราะห์ได้จากปรากฏการณ์นี้คือ:

### ⚠️ 2.1 บริบทถูกตัดขาด (Context Fragmentation)
เมื่อเราลดขนาด Chunk ลงเหลือ 1,000 (และเอกสารโรคข้าวของเราค่อนข้างสั้น) กลายเป็นว่าข้อมูลสำคัญของโรคนั้นๆ ถูกหั่นแยกออกจากกันมากเกินไป (จาก 10 Chunks ใน V4 กลายเป็น 15 Chunks ใน V5)
เมื่อระบบดึงมา 5 Chunks (Top-K=5) มันอาจจะดึงส่วนของเนื้อหามาแบบ **"แหว่งๆ"** ขาดความปะติดปะต่อ ทำให้ LLM ไม่สามารถเข้าใจความหมายแฝงหรือเรียบเรียงคำตอบที่สละสลวยได้เต็มที่ (สังเกตได้จาก **Context Precision ที่ร่วงหนักถึง 8.4%**)

### ⚠️ 2.2 ปัญหา Context Recall ไม่ได้เกิดจากก้อนใหญ่
เราคาดหวังว่า Chunk ที่เล็กลงจะช่วยให้ตัวตรวจ (LLM Judge) หาเนื้อหาเจอง่ายขึ้น แต่คะแนน Context Recall กลับลดลงจาก 19.9% เหลือ 19.1% สิ่งนี้บอกใบ้ว่า:
ปัญหาของ Context Recall ไม่ใช่ว่า "ก้อนมันใหญ่ไปจนหาไม่เจอ" แต่ปัญหาคือ **"บริบทมันขาดหายไปจากก้อนนั้นๆ"** พอเราหั่นเล็กลง บริบทที่จำเป็นสำหรับการตอบคำถามบางข้อกลับตกหล่นหายไประหว่างรอยต่อของ Chunk

## 🛠️ 3. ข้อสรุปและทิศทางในอนาคต (Next Steps)

การทดลอง V5 นี้ให้คำตอบทางสถาปัตยกรรมที่ชัดเจนมากครับ:
**"สำหรับเอกสารโรคข้าวชุดนี้ การใช้ Chunk Size ขนาด 1,500 ตัวอักษร (เหมือนใน V4) เป็น Sweet Spot ที่เหมาะสมที่สุดแล้ว"** เพราะมันช่วยรักษาสภาพแวดล้อมและบริบทของโรคไว้ได้ครบถ้วนกว่า

**🎯 การตัดสินใจ:**
1. เราควร **Revert ค่ากลับไปใช้การตั้งค่าของ V4** (Chunk=1500, Overlap=300) เพราะเป็นจุดที่ดึงประสิทธิภาพของ Faithfulness และ Answer Relevancy ออกมาได้สูงสุด
2. ข้ามการจมปลักอยู่กับการรีดคะแนน RAGAS ที่จุดนี้ แล้วนำ Base System (V4) เข้าสู่ **Phase 6: LINE + n8n Integration** เพื่อให้เกิดระบบที่จับต้องได้จริง เพราะคุณภาพคำตอบของ V4 นั้นผ่านเกณฑ์สำหรับการใช้งานจริงแล้วครับ
