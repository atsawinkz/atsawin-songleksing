#### ก.1.2 การใช้งานเมนูหลัก (Rich Menu)
ที่แถบด้านล่างของหน้าจอห้องแชทจะแสดงเมนูลัด (Rich Menu) ให้กดใช้งานได้อย่างสะดวกรวดเร็ว โดยแบ่งออกเป็น 3 ปุ่มคำสั่งหลัก ได้แก่:
1. **ถ่ายภาพตรวจโรคข้าว (TAKE DIAGNOSIS PHOTO):** เมื่อกดปุ่ม ระบบจะเปิดกล้องถ่ายรูปบนโทรศัพท์มือถือ เพื่อให้เกษตรกรสามารถเล็งถ่ายภาพใบข้าวที่มีอาการผิดปกติจากแปลงนาส่งตรวจได้ทันที
2. **ส่งภาพตรวจโรคข้าว (SUBMIT DISEASE PHOTO):** เมื่อกดปุ่ม ระบบจะเปิดคลังภาพ (Gallery) หรืออัลบั้มในโทรศัพท์ เพื่อให้เลือกรูปภาพใบข้าวที่เคยถ่ายเก็บไว้ส่งเข้ามาให้ระบบวิเคราะห์
3. **วิธีการใช้งานแชทบอท (CHATBOT USER GUIDE):** เมื่อกดปุ่ม ระบบจะส่งข้อความแนะนำขั้นตอนการใช้งานระบบ 3 ขั้นตอน และเทคนิคการถ่ายภาพใบข้าวระยะใกล้ให้คมชัด พร้อมตัวอย่างคำถามที่สามารถพิมพ์ถามบอทได้

#### ก.1.3 การส่งรูปภาพใบข้าวเพื่อตรวจวินิจฉัยโรค
เมื่อพบใบข้าวที่มีอาการผิดปกติในแปลงนา สามารถส่งรูปให้บอทตรวจได้ตามขั้นตอนนี้:
1. กดที่ปุ่ม **"ถ่ายภาพตรวจโรคข้าว"** เพื่อเปิดกล้องถ่ายภาพจริงในแปลงนา หรือกดปุ่ม **"ส่งภาพตรวจโรคข้าว"** เพื่อเลือกรูปภาพที่มีอยู่ในเครื่อง
2. **คำแนะนำในการถ่ายรูป:**
   - ควรถ่ายภาพใบข้าวในระยะใกล้ (ประมาณ 15–30 เซนติเมตร) ให้เห็นรอยโรคชัดเจนอยู่บริเวณกึ่งกลางภาพ
   - ถ่ายในจุดที่มีแสงสว่างเพียงพอ หลีกเลี่ยงภาพเบลอ ภาพสั่น หรือการถ่ายย้อนแสงแดดจัด
   - หลีกเลี่ยงการถ่ายภาพมุมกว้างที่เห็นทั้งแปลงนา เพราะ AI จะมองไม่เห็นรายละเอียดของแผล
3. กดปุ่ม **"ส่ง"** รูปภาพเข้าสู่ห้องแชท
4. ระบบจะส่งข้อความแจ้งเตือนสถานะการประมวลผลให้ผู้ใช้ทราบว่ากำลังวิเคราะห์รูปภาพ

#### ก.1.4 การรับผลการวินิจฉัยโรคและคำแนะนำการรักษา
เมื่อระบบประมวลผลภาพเสร็จสิ้น แชทบอทจะส่งข้อความตอบกลับในรูปแบบข้อความตัวหนังสือที่มีโครงสร้างชัดเจนและอ่านง่าย ประกอบด้วย 2 ส่วนสำคัญ ได้แก่:
1. **🌾 ผลการวินิจฉัยโรคข้าว:** ระบุชื่อโรคข้าวที่ตรวจพบ (เช่น โรคใบจุดสีน้ำตาล, โรคไหม้ข้าว, โรคขอบใบแห้ง) พร้อมระบุระดับความมั่นใจของโมเดล (Confidence Score เช่น ความมั่นใจ 85.8%)
2. **💡 คำแนะนำและการรักษา:** สรุปวิธีปฏิบัติตามคู่มือวิชาการของกรมการข้าว กระทรวงเกษตรและสหกรณ์ ได้แก่:
   - การเตรียมเมล็ดพันธุ์ก่อนปลูกและการใช้เชื้อราไตรโคเดอร์มา
   - การจัดการแปลงนา การควบคุมน้ำ และการงดใส่ปุ๋ยไนโตรเจนชั่วคราว
   - การใช้สารเคมีป้องกันกำจัดโรคพืช (ชื่อสารเคมีที่แนะนำ เช่น ไตรไซคลาโซล, แมนโคเซบ, คาร์เบนดาซิม, คาซูกาไมซิน) พร้อมอัตราส่วนผสมที่ปลอดภัย

#### ก.1.5 การพิมพ์ข้อความสอบถามข้อมูลโรคข้าวเพิ่มเติม

#### ก.2.4 การจัดการฐานข้อมูลความรู้เวกเตอร์ (Pinecone Vector Database)

2. เลือกดูรายละเอียด Index ประจำโครงงาน ชื่อ **`rice-knowledge`**
3. ตรวจสอบข้อมูลสถิติที่สำคัญ:
   - **Index Name:** `rice-knowledge` (Type: Dense, Region: aws us-east-1)
   - **Record Count:** จำนวนชิ้นข้อมูลความรู้โรคข้าว (Chunks) ที่จัดเก็บอยู่ในระบบ (เช่น 10 Chunks)
   - **Records:** รายการข้อมูลความรู้ของแต่ละโรค เช่น `bacterial_leaf_blight_chunk_0`, `leaf_blast_chunk_0`, `sheath_blight_chunk_0`
   - **Usage / Latency:** กราฟแสดงความถี่ในการสืบค้นข้อมูลและเวลาที่ใช้ในการค้นหา

#### ก.2.6 การจัดเตรียมชุดข้อมูลภาพถ่ายใบข้าว (Dataset Directory Structure)
กรณีที่ผู้ดูแลระบบต้องการเพิ่มภาพตัวอย่างโรคข้าวใหม่ หรืออัปเดตข้อมูลเพื่อฝึกฝนโมเดลตรวจจับโรคข้าว (RT-DETR) ใหม่ จะต้องจัดโครงสร้างโฟลเดอร์ตามมาตรฐาน YOLO / Ultralytics ภายใต้ไดเรกทอรี `data/labeled_datacentric-blb/` ดังนี้:

```text
data/labeled_datacentric-blb/
├── train/
│   ├── images/          # ไฟล์ภาพใบข้าวสำหรับฝึกฝน (.jpg, .png)
│   └── labels/          # ไฟล์พิกัดกรอบรอยโรค (.txt)
├── valid/
│   ├── images/          # ไฟล์ภาพใบข้าวสำหรับตรวจสอบระหว่างฝึกฝน
│   └── labels/          # ไฟล์พิกัดกรอบรอยโรค (.txt)
└── test/
    ├── images/          # ไฟล์ภาพใบข้าวสำหรับทดสอบวัดค่าความแม่นยำ
    └── labels/          # ไฟล์พิกัดกรอบรอยโรค (.txt)
```

โดยไฟล์พิกัดระบุตำแหน่งรอยโรคในโฟลเดอร์ `labels/` จะต้องมีชื่อตรงกับไฟล์ภาพ และบันทึกข้อมูลในรูปแบบพิกัดมาตรฐาน (Normalized Bounding Box 0.0 - 1.0):
`<class_id> <x_center> <y_center> <width> <height>`

ตัวอย่างข้อมูลในไฟล์ `.txt`:
`0 0.453125 0.612500 0.187500 0.358333`
(ความหมาย: รอยโรคคลาส 0 คือโรคขอบใบแห้ง มีจุดศูนย์กลางแผลที่พิกัด x=45.3%, y=61.2% ความกว้าง 18.7% และความสูง 35.8% ของภาพ)


#### ก.2.7 การติดฉลากระบุตำแหน่งรอยโรคบนใบข้าว (Data Annotation)
การตีกรอบระบุตำแหน่งรอยโรคบนภาพถ่ายใบข้าว (Bounding Box Annotation) สามารถทำผ่านโปรแกรมติดฉลาก เช่น **Roboflow** หรือ **LabelImg** ตามขั้นตอนดังนี้:
1. นำเข้าไฟล์ภาพถ่ายใบข้าวชุดใหม่เข้าสู่โปรแกรม
2. เลือกตีกรอบสี่เหลี่ยม (Bounding Box) ล้อมรอบเฉพาะบริเวณรอยโรคที่เกิดขึ้นจริงบนใบข้าวอย่างแม่นยำ
3. กำหนดชื่อคลาสของโรคให้ตรงกับรหัสคลาสทั้ง 5 โรค:
   - `0: bacterial_leaf_blight` (โรคขอบใบแห้ง)
   - `1: brown_spot` (โรคใบจุดสีน้ำตาล)
   - `2: leaf_blast` (โรคใบไหม้)
   - `3: leaf_scald` (โรคใบขอบกาบแห้ง)
   - `4: sheath_blight` (โรคกาบใบแห้ง)
4. **แนวทางปฏิบัติเพื่อความแม่นยำสูง (Data-Centric AI Guideline):** สำหรับโรคขอบใบแห้งที่มีแผลยาวตามแนวใบ ให้ตีกรอบยาวต่อเนื่องครอบคลุมแผลทั้งหมดเป็นกรอบเดียว หลีกเลี่ยงการตีกรอบสี่เหลี่ยมย่อย ๆ ซ้อนทับกันหลายกรอบ เพราะจะทำให้โมเดลสับสนในการตรวจจับ
5. ทำการส่งออกข้อมูล (Export) ในรูปแบบ **YOLO format** แล้วนำไปจัดเก็บลงในโฟลเดอร์ `images/` และ `labels/` โดยแบ่งสัดส่วนเป็น Train 70%, Validation 20% และ Test 10%

```
+-------------------------------------------------------------------------+
|                                                                         |
|                       [ พื้นที่สำหรับวางรูปภาพ ]                         |
|                                                                         |
+-------------------------------------------------------------------------+
ภาพที่ ก-13 ตัวอย่างการตีกรอบรอยโรคบนใบข้าว (Annotation) ด้วยโปรแกรม Roboflow
(คำอธิบายรูป: ภาพหน้าจอการตีกรอบสี่เหลี่ยมระบุรอยโรคบนใบข้าว พร้อมการกำหนดชื่อคลาสโรคตามแนวทาง Data-Centric AI)
```

#### ก.2.8 การกำหนดค่าคอนฟิกและการฝึกสอนโมเดล RT-DETR (Model Training & Evaluation)
เมื่อจัดเตรียมชุดข้อมูลและติดฉลากเรียบร้อยแล้ว ผู้ดูแลระบบสามารถฝึกสอนโมเดลได้ตามขั้นตอนนี้:
1. ตรวจสอบไฟล์คอนฟิก `training/dataset_v5.yaml` เพื่อระบุตำแหน่งโฟลเดอร์ข้อมูลและรายชื่อคลาส:
   ```yaml
   path: ../data/labeled_datacentric-blb
   train: train/images
   val: valid/images
   test: test/images

   nc: 5
   names:
     0: bacterial_leaf_blight
     1: brown_spot
     2: leaf_blast
     3: leaf_scald
     4: sheath_blight
   ```
2. เปิด Terminal ในเครื่องเซิร์ฟเวอร์ และรันคำสั่งฝึกสอนโมเดลด้วยสคริปต์ `training/train_rtdetr_v5.py`:
   ```bash
   python training/train_rtdetr_v5.py
   ```
3. สคริปต์จะทำการโหลดน้ำหนักตั้งต้นและเริ่มการฝึกสอนโมเดล RT-DETR-L บนหน่วยประมวลผลกราฟิก (GPU) พร้อมทั้งแสดงค่าความสูญเสีย (Loss) และค่าความแม่นยำ (mAP@0.5) ในแต่ละ Epoch
4. เมื่อฝึกสอนเสร็จสิ้น ระบบจะบันทึกไฟล์น้ำหนักโมเดลที่ดีที่สุดไว้ที่:
   `training/runs/detect/runs/rtdetr_rice_v5/weights/best.pt`
5. ประเมินประสิทธิภาพโมเดลบนชุดข้อมูลทดสอบมาตรฐาน (Test Set) ด้วยคำสั่ง:
   ```bash
   python training/evaluate_model.py
   ```
6. นำไฟล์โมเดล `best.pt` ที่ได้ไปวางในระบบ API เพื่อให้ระบบพร้อมใช้งานตรวจจับโรคข้าวเวอร์ชันใหม่ผ่านแชทบอท LINE ทันที

```
+-------------------------------------------------------------------------+
|                                                                         |
|                       [ พื้นที่สำหรับวางรูปภาพ ]                         |
|                                                                         |
+-------------------------------------------------------------------------+
ภาพที่ ก-14 หน้าต่าง Terminal ขณะดำเนินการฝึกสอนโมเดล RT-DETR-L (Training Execution)
(คำอธิบายรูป: ภาพหน้าจอ Terminal แสดงสถานะการรันคำสั่งฝึกสอนโมเดล การประมวลผลแต่ละ Epoch และผลลัพธ์การบันทึกไฟล์ best.pt สำเร็จ)
```
